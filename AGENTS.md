- **Post-login "bounce" fix — stale-token 401 evicts a newer session (frontend, `src/utils/apiClient.js` only)**: Root-caused the bug where the Dashboard opens ~2s after login and then auto-redirects to Login. Chain (proven with a deterministic cross-tab harness): a request carrying an OLD/stale `bugflow_token` (e.g. a deleted/expired account) is already in flight; a fresh login writes a NEW token to the same shared `bugflow_token` localStorage key; the stale request's 401 lands late → `handleResponse` → `refreshAccessToken()` fails (session gone) → `handleLogout()` **unconditionally** removed `bugflow_token` → evicted the NEW session → storage event in the fresh tab → `AuthContext` reset → `RequireAuth` rendered `<LoginPage/>` (the visible bounce). ## Key Decisions
- Backend `ApiResponse` wraps all responses as `{ success, message, data }`; frontend `apiClient.js` returns the full JSON object
- Backend model field names differ from frontend: `projectName` (not `name`), `bugId` (not `id`), `testCaseId` (not `id`), `_id` (not `id`)
- Bug model has two status fields: `status` (lifecycle) and `workflowStatus` (Kanban columns)
- AI endpoints under `/api/ai/*` (7 features + history + stats)
- Analytics endpoint `GET /api/analytics/dashboard` returns one payload `{ summary, healthScore, charts, tables, ai, insights, filterOptions }`; every filter change refetches it
- Release endpoints under `/api/releases` (auth-protected): GET /, GET /:id, GET /stats, GET /meta, GET /next-version, GET /export, POST /, PUT /:id, DELETE /:id; KPI keys match ReleaseKPICards (upcoming/releasedToday/pendingQA/blocked/production/hotfixes/rollbackCandidates/successRate)
- All backend routes use auth middleware; frontend stores token in `localStorage` as `bugflow_token`
- Auth flow: `bf_refresh` httpOnly cookie carries the refresh token (30d, sha256 on `LoginSession`); access token (15m, JWT with `sid`) in `Authorization: Bearer` from localStorage `bugflow_token`; silent refresh on 401 (single-flight dedupe, one retry) via `POST /api/auth/refresh`; JWT carries `sv` claim checked against user `sessionVersion`; logged-out/terminated sessions 401 on first access-token use
- Strong-password policy (≥8, upper+lower, digit, special) enforced at register, password change, and reset; RBAC roles: Admin/Manager/QA Lead/Project Manager/Developer/Viewer (default `Viewer`)
- Role requests: eligible target roles are server-computed from `REQUESTABLE_ROLES` (`Viewer`→`QA Engineer`/`QA Lead`/`Developer`/`Project Manager`, `QA Engineer`→`QA Lead`); only `Admin`/`Manager` review (`ROLE_REVIEW_ROLES`); queue supports `status=All`; approve/reject/status/reviewer always backend-set, never frontend; **invalid requested roles now return HTTP 400** (service `createRoleRequest` throws 400 for ineligible; validator 400 for non-enum roles like `QA Manager`)
- Project list/detail access is role-scoped on the backend: privileged = Admin/Manager/QA Lead/Project Manager (see all); everyone else sees only projects they own/created/are on/`Public`; missing → 404, inaccessible → 403
